# Database-per-service ownership, one shared Postgres container

Each service (Notification API, Email/SMS/Push Channel Services) owns its data exclusively: no service queries another's tables, and each gets its own logical database. Physically, all logical databases run in a single Postgres container in docker-compose rather than one container per service — this is purely a resource/startup-time convenience for a local learning environment and must not be read as looser isolation. Nothing in the code may assume co-location; connection strings are per-service and scoped to one database each, so splitting into separate containers later is a docker-compose change only, never a code change.

## Provisioning and enforcement

Each service provisions its own database: EF Core `Migrate()` runs at service startup (behind a bounded connection retry, since a healthy Postgres container is not necessarily ready for the next connection), creating the database if absent and applying that service's migrations. There is no init SQL script — the schema of a service's database is owned by that service's migrations and nothing else, and the Postgres container starts empty and knows nothing about its tenants. `EnsureCreated()` is deliberately not used: it bypasses the migrations history table that the MassTransit outbox's own migrations depend on.

The cost is that a self-provisioning service needs `CREATEDB`, which is wider than the "scoped to one database each" grant described above. All services therefore connect as one shared superuser, and **the ownership boundary is enforced by convention, not by grants**: each service's connection string names only its own database, and no code opens a connection to another's. Nothing at the database level would stop a service from reading its neighbour's tables — so a violation is caught by review, not by an error. Tightening this means introducing per-service roles, which needs an actor that runs `CREATE ROLE` before any service starts (an init script or a migration container) — a change to this ADR, not something to bolt on quietly.
